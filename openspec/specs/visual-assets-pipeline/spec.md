# visual-assets-pipeline Specification

## Purpose
The visual-assets-pipeline capability establishes the mandatory quality and architectural standards governing all visual assets (actor tokens, sheet portraits, item icons, and ability graphics) across all compendiums in `compendios-para-t20`.

## Requirements

### Requirement: Exclusive 2-Minute Tabletop Actor Token Architecture
Every Actor's prototype token (`prototypeToken.texture.src`) SHALL be sourced exclusively from the hand-drawn top-down collection of the 2-Minute Tabletop (`https://2minutetabletop.com/`). Third-party tokens, system default tokens (`mystery-man.svg`), or non-2MTT art MUST NOT be assigned to actor prototype tokens.

#### Scenario: Assigning a token to any threat or NPC actor
- **GIVEN** any threat or NPC actor created or updated in `Ameacas_T20`
- **WHEN** the actor's prototype token is configured via `create-entry.js` or `icon-resolver.js`
- **THEN** `prototypeToken.texture.src` resolves strictly to `modules/compendios-para-t20/assets/tokens/<actor-slug>.png`
- **AND** the token image is a valid 8-bit RGBA transparent PNG from 2-Minute Tabletop

### Requirement: Automated Token and Grid Dimension Synchronization
The dimensions (`prototypeToken.width` and `prototypeToken.height`) of an Actor's token SHALL be automatically synchronized with the creature's canonical size category (`system.detalhes.tamanho` and `system.tracos.tamanho`):
- Minúsculo / Pequeno / Médio: 1x1 grid squares
- Grande: 2x2 grid squares
- Enorme: 3x3 grid squares
- Colossal: 4x4 grid squares

#### Scenario: Token dimensions for Enorme or Grande creature
- **GIVEN** an actor with size `eno` (e.g. Lynel ND 12) or `gra` (e.g. Tyrant ND 10, Enxame de Armas ND 4)
- **WHEN** the actor document is constructed
- **THEN** `prototypeToken.width` and `prototypeToken.height` are set to 3 for Enorme, and 2 for Grande
- **AND** the token properly occupies the corresponding grid cells when dragged to the scene

### Requirement: Thematic Multi-Source Sheet Portrait and Item Icon Pipeline
Sheet portraits (`actor.img`) and item icons (`item.img`) SHALL be resolved through the automated multi-source pipeline implemented in `scripts/icon-resolver.js`:
1. Native Tormenta20 canonical icon artwork (`systems/tormenta20/icons/...`)
2. High-resolution full-color themed icons from Wowhead / World of Warcraft (`modules/compendios-para-t20/assets/icons/...`)
3. Themed vector icons from Game-Icons.net with Foundry dark-mode styling
Generic placeholder icons (`mystery-man.svg`, `item-bag.svg`, `combat.svg`) MUST NOT be used.

#### Scenario: Automatic icon resolution for an item or power
- **GIVEN** an item created without an explicit image path
- **WHEN** `resolveIcon({ name, type })` executes
- **THEN** it matches canonical keywords and returns the most thematic icon
- **AND** if an online asset is requested, it downloads and caches the file in `assets/icons/`

### Requirement: Asset Bundling in Distribution Zip
All custom tokens in `assets/tokens/` and custom icons in `assets/icons/` SHALL be included in `module.zip` generated by `npm run zip` and the GitHub Actions release workflow, ensuring immediate availability on any user's Foundry VTT installation.

#### Scenario: Compiling module zip for release
- **GIVEN** an active release workflow triggered by a tag push
- **WHEN** the zip command executes
- **THEN** `assets/tokens/` and `assets/icons/` are bundled into `module.zip`
- **AND** all image paths in LevelDB match the distributed folder structure
